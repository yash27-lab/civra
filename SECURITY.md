# Security policy

## Reporting a vulnerability

Do not open a public issue for a vulnerability involving owner documents, access controls, source evidence, session handling, or the Solari integration.

Use GitHub's private security advisory flow for this repository and include:

- the affected release or commit;
- minimal, synthetic reproduction steps;
- expected and observed behavior; and
- the security impact.

Do not include real owner documents, access codes, session cookies, API keys, or private city-account information.

## Scope

Civra's security boundaries include source-evidence integrity, fail-closed document review, private sessions, server-only credentials, and the ephemeral document sandbox. A report that shows a boundary can be bypassed is in scope.

Civra does not claim compliance certification. Treat the repository's safeguards as implementation controls that still need deployment-specific review.
